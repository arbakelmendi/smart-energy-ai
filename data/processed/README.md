# Processed data

`energydata_cleaned.csv` is generated from the UCI Appliances Energy Prediction raw CSV by `ml/src/preprocess.py`. The pipeline never modifies the raw CSV. It removes only `rv1` and `rv2`, which are identical row by row and are random/questionable rather than physical variables. No observations or target outliers are removed.

`energydata_features.csv` is generated reproducibly from the cleaned CSV by `ml/src/feature_engineering.py` for one-step-ahead prediction at a 10-minute horizon. It retains the current-time `Appliances` input and creates the next-observation target, approved temporal/cyclical features, historical lags through 7 days, and backward-looking rolling statistics.

The first 1,008 rows are excluded because the required 7-day historical context is unavailable; the final row is excluded because its next-step target is unavailable. These are supervised-sample alignment exclusions, not data cleaning.

`energy_train.csv`, `energy_validation.csv`, and `energy_test.csv` are generated reproducibly from the feature dataset by `ml/src/split_data.py` using contiguous chronological 70%/15%/15% partitions. Split boundaries, checksums, and the model feature schema are recorded in `ml/results/split_metadata.json` and `ml/results/feature_schema.json`.

Generated CSV files are ignored by Git; do not force-add them. Phase 7 compares persistence with Linear Regression using validation-only metrics in `ml/results/phase7_validation_metrics.json`; its StandardScaler is fitted on training rows only. Phase 8 adds an untuned Random Forest validation comparison in `ml/results/phase8_random_forest_validation_metrics.json`, using no scaling and `random_state=42`. Phase 9 adds an untuned XGBoost validation comparison in `ml/results/phase9_xgboost_validation_metrics.json`, using deterministic CPU settings and no scaling. Phase 10 tuned the tree models using TRAIN-only expanding cross-validation. Phase 11 selects the final model by saved validation RMSE only, locks its configuration, refits on TRAIN + VALIDATION, and only then evaluates the selected model on the held-out TEST split. Final held-out estimates are recorded in `ml/results/phase11_final_test_evaluation.json`; no post-test tuning is performed. No model artifact is persisted. See `ml/notebooks/10_final_model_evaluation.ipynb` for final metrics and diagnostic plots. Generated predictions and plots under `ml/results/generated/` are Git-ignored. The evaluation refuses to overwrite the first result; `--verify-reproducibility` permits only an identical technical replay.
